# `analysis.md` 模板

题解关注「为什么这样做」而不是「代码长什么样」。代码细节让 `ac.cpp` 说话，题解只写思路链路与关键观察。

```markdown
# X. <题目标题> — 题解

## 算法标签
DP / 数据结构 / 数论 / 贪心 / 图论 / 字符串 / 计算几何 / 构造 / 交互 / …
（多个用 `、` 隔开）

## 关键观察
- 观察 1：…
- 观察 2：…

## 思路
<从观察推到算法的链路。可以分段：
1. 把问题转化成 …
2. 注意到 …，可以用 … 维护
3. 答案即为 …>

## 实现要点
- 数据结构：树状数组 / 线段树 / set / …
- 边界：n = 1 / 全相同 / 空集 …
- 多组数据：每组前要重置 …

## 复杂度
- 时间：$O(n \log n)$
- 空间：$O(n)$

## 易错点
- …
- …

## 参考
- 官方题解：<链接，可选>
- 类似题：<链接，可选>
```

## 约定

- 不贴整段代码；可用「伪代码块」或行内 `code` 提关键片段
- 复杂度必须给，哪怕是 $O(2^n)$ 也写明
- 如果有多种做法，主做法对应 `ac.cpp`，备选做法放 `## 备选做法` 一节简述
