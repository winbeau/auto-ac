# E. 保卫城邦 — 题解

> ⚠️ **待验证**：当前 `ac.cpp` 为暴力 best-effort 版本：每次操作后**整树重算**树形 DP。
> 单次 $O(n)$、总体 $O(nm)$，在 $n=m=2\times 10^5$ 时会 TLE。两组样例都能过，DP 正确性应该没问题；
> 想要 AC 需要将整树重算替换为支持动态加边/删边的数据结构（LCT 维护 cluster DP，或 Top Tree）。
> 卡点：动态树形 DP 状态合并的设计与 LCT/Top Tree 实现都比较繁，未在 60 分钟预算内完成。

## 算法标签
树形 DP、动态树 / LCT、最小点覆盖变种

## 关键观察
- **每个城邦最优驻军数 $\le 2$**：超过 2 不会带来额外收益（一个邻居只能"看到"该节点的全部驻军，但要求只到 2 为止）。所以每个节点的状态 $\in \{0, 1, 2\}$。
- **约束局部化**：约束只在每条边的两端之间产生作用——对未驻军节点 $v$，是邻居驻军和 $\ge 2$。因此可以做树形 DP。
- **样例 2** 的所有答案均为 5，提示答案对小幅度树形变化稳健，符合"动态维护"的题意。

## 思路
设根为 1，对每个节点 $v$ 维护五个状态值（参数：父贡献 $p \in \{0,1,2\}$，自身驻军 $x_v$）：

| 名称 | $x_v$ | 父贡献 $p$ | 含义 |
|---|---|---|---|
| $f_0[v]$ | 0 | 2 | $v$ 已被父覆盖，子节点贡献无要求 |
| $f_1[v]$ | 0 | 1 | $v$ 还差 1，需子节点贡献和 $\ge 1$ |
| $f_2[v]$ | 0 | 0 | $v$ 需子节点贡献和 $\ge 2$ |
| $g_1[v]$ | 1 | 1 | $v$ 驻 1 |
| $g_2[v]$ | 2 | 2 | $v$ 驻 2 |

转移（设 $c$ 是 $v$ 的子节点）：
- $f_0[v] = \sum_c \min(f_2[c], g_1[c], g_2[c])$；
- $g_1[v] = 1 + \sum_c \min(f_1[c], g_1[c], g_2[c])$；
- $g_2[v] = 2 + \sum_c \min(f_0[c], g_1[c], g_2[c])$；
- $f_1[v]$：贡献由 $f_1[c]$（0）/ $g_1[c]$（1）/ $g_2[c]$（2）三选一，需总贡献 $\ge 1$。等价"如果默认全选 $f_1[c]$ 还差 1，则升级一个 $c$ 到 $\min(g_1[c], g_2[c])$，挑增量最小的"。
- $f_2[v]$：同上，但需要总贡献 $\ge 2$。用一维 0/1/2 背包逐子节点合并即可（状态数 3）。

根节点没有父，等价 $p=0$，答案 $= \min(f_2[1], g_1[1], g_2[1])$。

**操作维护**：每次操作把树从 $T$ 改成 $T'$，要在 $O(\log n)$ 内重算上述 DP。这需要：
1. LCT / Top Tree 维护每个簇 (cluster) 的 DP 矩阵（描述簇接口状态间的最优转移）。
2. 合并两个簇是 min-plus 矩阵乘积，状态数小（5 左右），常数可接受。
3. 加边 = link，删边 = cut，然后查询全局根。

主流写法是 **Top Tree**（处理 rake / compress 两种合并），所有合并都基于状态转移矩阵。复杂度 $O((n + m)\log n)$。

## 实现要点
- **状态压缩**：可以把 $\{f_0, f_1, f_2, g_1, g_2\}$ 看作 5 个"已经把 $x_v$ 决策好的版本"。簇接口矩阵的行/列就是这 5 个状态。
- **min-plus 乘积**：$25 \times 5 = 125$ 次加法 + 比较，常数较小。
- **断边重连**：操作保证树仍然连通，可直接 cut + link。
- **当前 `ac.cpp` 用 multiset 维护邻接以便 $O(\log n)$ 删边**；重算 DP 是 $O(n)$，瓶颈在 DP 重算。
- **迭代 DFS**：$n = 2\times 10^5$ 链状树会爆栈，必须用 BFS / 显式栈得到拓扑序后倒序处理。

## 复杂度
- 当前 best-effort：$O(nm)$ 时间 / $O(n)$ 空间——会 TLE，但样例通过且 DP 正确。
- 目标 AC（未实现）：$O((n+m)\log n)$ 时间 / $O(n)$ 空间（Top Tree / LCT 维护 cluster DP）。

## 易错点
- 容易把"邻居共 $\ge 2$"错误理解成"每个邻居 $\ge 2$"或"至少 2 个邻居驻军"。题意是**邻居驻军总数** $\ge 2$。
- $f_1[v]$ 求和时要小心"全部子节点都选 $f_1[c]$ 导致没有贡献者"的边界——需要找最小的升级代价。
- $f_2[v]$ 用 0/1/2 背包合并（不要直接套两次 "升级"），否则当某子节点直接选 $g_2[c]$ 比两个 $g_1$ 更便宜时会错。
- 叶子节点：没有子，$f_1, f_2$ 必须置 $\infty$。
- 根节点：等价 $p = 0$，答案应取 $\min(f_2[1], g_1[1], g_2[1])$，**不**包含 $f_0, f_1$。
