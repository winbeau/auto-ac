# J. 排列与合数 — 题解

## 算法标签
构造、数论（素数筛）、枚举

## 关键观察
- 观察 1：$n$ 仅有 $5$ 位且数位互不相同，所有数位排列总数仅 $5! = 120$ 个，规模极小，可以直接枚举。
- 观察 2：在 $[10^4, 10^5)$ 范围内，素数仅有约 $8000$ 个，合数密度远高于素数（约 $11/12$）。绝大多数情况下排列里有大量合数，第一遍枚举几乎必然命中。
- 观察 3：只有当 $n$ 的数位排列得到的所有合法 $n'$（即 $\ge 10000$ 的无前导零排列）全部为素数时才输出 $-1$。在本数据范围下几乎不出现这种情形，但仍需保留该分支以保证正确性。

## 思路
1. **预处理素数表**：用埃氏筛 / 线性筛预处理 $[2, 10^5)$ 内的素数 / 合数标记 `is_prime[]`，复杂度 $O(N \log \log N)$ 或 $O(N)$。
2. **每组询问**：
   - 把 $n$ 的 $5$ 个数位提取成 `string`，`sort` 得到字典序最小排列。
   - 用 `do { ... } while (next_permutation(...))` 枚举所有 $120$ 个排列：
     - 跳过首位为 `'0'` 的排列（题目要求无前导零）。
     - 把排列拼回整数 $v$，若 $v$ 是合数（`!is_prime[v]`），输出 $v$ 并跳出。
   - 若所有排列均为素数（或全部首位为 $0$，本数据范围不会发生），输出 $-1$。
3. **早停**：合数极多，第一个命中即返回，常数极小（期望试 $1\sim 2$ 次即可）。

## 实现要点
- 数据结构：`bool is_prime[100001]`，埃氏筛预处理。
- 提取数位：直接转 `string` 后用 `sort` + `next_permutation`，便于枚举。
- 边界：跳过首位 $0$；$n' = n$（恒等排列）是合法的，不需要排除（样例 1 第 1 行即输出 $12345$ 自身）。
- IO：$T \le 10^5$，必须 `ios::sync_with_stdio(false); cin.tie(nullptr);`。
- 多组数据：素数筛一次建好，每组只做枚举，无需重置。

## 复杂度
- 预处理：$O(N \log \log N)$，$N = 10^5$。
- 单组：最坏枚举 $120$ 个排列，每次 $O(5)$ 拼数 + $O(1)$ 查表。早停后期望 $O(1)$。
- 总：$O(N \log \log N + 120 \cdot T) \le 10^5 + 1.2 \times 10^7$，远在 1s 内。
- 空间：$O(N) = 10^5$ bool。

## 易错点
- 忘记跳过首位为 $0$ 的排列（题目要求 $n'$ 无前导零）。
- 误把 $n' = n$ 排除（题目和样例都允许恒等排列；样例 1 第 1 行输出即原数 $12345$）。
- 没有先用 `sort` 把数位串排成字典序最小再 `next_permutation`，会漏掉一半排列。
- `is_prime[v]` 数组要覆盖到 $99999$，开 `MAXN = 100000` 注意端点。
